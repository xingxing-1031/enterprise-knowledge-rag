# W8-2：分层与有界多跳 RAG

## 本阶段目标

把一次扁平 Top-K 检索拆成证据需求规划、授权父文档路由、章节检索、覆盖检查和最多一次补充检索。

## 业务问题

复合制度问题常同时需要主规则、材料、例外和办理流程。单次查询可能只命中其中一部分；无界 Agent 搜索又会放大成本、延迟和越权风险。

## 我的实现

结构化计划最多包含四个证据需求，`max_hops` 只能是 1 或 2。服务端先按身份、版本和时间筛选父文档，再在最多四份路由文档中查章节。若必需需求未覆盖，代码用缺失需求和已授权路由标题构造第二跳查询；第二跳不能扩张文档键集合。最终证据限制为 6 个章节和约 1200 token。

## 评测观测

工作流公开安全的路由文档键、hop 数、必需需求与覆盖需求。评分器新增父文档路由召回、需求覆盖、第二跳触发准确性、第二跳成功率和无关证据比例；冻结集仍保持锁定。

## 取舍

本实现不使用 GraphRAG、Neo4j、HyDE 或无界 Agentic Search。第二跳仍缺证据时在生成前拒答，生成模型不能补写企业规则。

## 可口述答案

第一跳解决“去哪些已授权文档找”，章节检索解决“具体证据在哪”，覆盖检查解决“必需事实是否齐全”。第二跳只是受控补证据，不是让模型自由浏览知识库。
