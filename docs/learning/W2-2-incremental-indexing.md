# W2-2：pgvector 与增量索引

## 本阶段目标

把版本化文档、片段和向量作为同一事务写入 PostgreSQL/pgvector，并跳过未变化文档。

## 业务问题

知识库更新时如果每次全量重建，会浪费 Embedding 成本；如果先删旧片段再写新片段但中途失败，线上会短暂丢失文档。不同版本共用一个文档 ID 时，还必须防止片段关联错误。

## 我的实现

文档表使用 `(document_id, version)` 复合主键，片段同时保存 `document_id` 和 `document_version`。索引服务根据内容哈希跳过未变化版本，检测相同内容被错误登记为另一个文档，并在单个数据库事务中更新文档、删除该版本旧片段和写入新向量。

## 验证结果

- 增量索引新增、跳过、重复内容和批次容错测试通过。
- 截至本阶段，本地 Python 回归测试共 24 项通过，pgvector 集成测试在未设置数据库开关时明确跳过。
- 当前 Codex 终端未发现 Docker 可执行文件，因此不能把真实空库 pgvector smoke 描述为已通过；Compose、迁移和往返测试入口已经保留，后续在 Docker 环境继续验收。

## 遇到的问题与取舍

建模时发现 `ChunkRecord` 只有 `document_id` 无法区分同一制度的 v1 和 v2，因此补充 `document_version`，数据库使用 `(document_id, version)` 复合主键。这个问题必须在持久化前修正，否则引用和向量会关联到错误版本。

## 我能口述的标准答案

增量索引不是只判断文件名。文件名可能不变但内容变化，也可能换了路径但内容重复。我使用规范化内容哈希判断是否需要重新生成向量，并把文档和所有片段放在同一个事务里更新。这样失败时可以整体回滚，不会出现文档元数据是新版、片段还是旧版的状态。

## 面试追问

- 为什么删除旧片段和写新片段必须在同一事务？
- 为什么内容哈希不能代替版本号？
