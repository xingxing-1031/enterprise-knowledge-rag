# W2-1：文档解析与标题感知切分

## 本阶段目标

把带 YAML 元数据的企业制度转换为稳定、可引用的文档片段。

## 业务问题

固定字符切块可能把标题、表格和例外条款拆开，模型即使召回了文本也不知道它属于哪个章节，引用和版本审计都不可靠。

## 我的实现

使用 YAML 解析器校验 front matter，运行时生成内容哈希和索引时间。切分时维护 Markdown 标题栈，在同一章节内按段落、列表和表格块组合，超出预算时再细分；每个片段保存完整 `section_path` 和由文档、版本、章节、序号及内容生成的稳定 `chunk_id`。

## 验证结果

- 文档解析与切分专项测试：8 项通过。
- 全部 Python 回归测试：20 项通过。
- Ruff 规则检查与格式检查通过。
- 示例制度在 `max_tokens=80` 时生成 4 个片段，每个片段均未跨越章节，最大近似 token 数为 73。

## 遇到的问题与取舍

当前 token 预算使用确定性中文字符与英文单词近似值，便于本地和 CI 复现。真实 Embedding 接入后会记录模型 token 统计差异，但不会让 tokenizer 反向改变引用标识。

## 我能口述的标准答案

切块不是越小越好。太小会丢失条款上下文，太大又会引入无关内容。我先按标题层级隔离章节，再尽量保留段落、列表和表格边界，只有单个块过大时才继续拆。每个 chunk 保留章节路径和稳定 ID，所以回答引用可以准确回到文档版本和章节。
