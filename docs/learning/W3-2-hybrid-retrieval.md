# W3-2：BM25、向量召回与 RRF

## 本阶段目标

实现两条互补召回通道，并使用排名融合得到可解释的候选列表。

## 业务问题

制度编号、标题和专有名词适合关键词检索，用户口语化改写适合向量检索。BM25 分数和余弦相似度不在同一量纲，直接相加会让分值范围更大的一路支配结果。

## 我的实现

BM25 索引同时使用文档标题、稳定 ID、章节路径和正文，并使用 jieba 搜索模式处理中文。向量适配器要求每次传入已经授权的文档版本集合。RRF 根据每路排名计算融合分，候选保留命中通道和原始名次。

## 验证结果

- BM25、向量适配和 RRF 专项测试：8 项通过。
- 全部 Python 回归：43 项通过，1 项 pgvector 环境测试明确跳过。
- 测试覆盖双路共同命中优先、单通道重复去重、融合后截断和无授权版本时不访问向量后端。

## 遇到的问题与取舍

在只有两条候选的小语料测试中，Okapi BM25 的 IDF 可能让共同词得分为 0，原实现过滤非正分后返回空列表。修复后仍以 BM25 为主排序，同时使用查询词项重合数稳定处理零分并过滤完全不重合候选，而不是针对某个问题硬编码关键词。

## 我能口述的标准答案

BM25 和向量检索解决的是不同问题。BM25 对制度名称、编号和金额等字面信息更稳定，向量检索能找出表达不同但语义相近的片段。它们的原始分数不能直接比较，所以我用 RRF 按各自排名融合；两路都靠前的候选会得到更高融合分，同时不会因为某一路分值范围更大而垄断结果。
