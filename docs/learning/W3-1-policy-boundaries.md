# W3-1：权限预过滤与生效版本决议

## 本阶段目标

在候选正文进入检索模型和 LLM 前，确定当前用户可见的文档和唯一有效版本。

## 业务问题

如果先把受限文档交给模型再要求它不回答，内容已经越过了权限边界。相似度也无法判断草案、废止版和当前生效版，错误版本即使回答流畅也属于业务错误。

## 我的实现

权限规则区分公开、部门和受限文档：部门文档要求部门匹配，受限文档同时要求角色和部门；知识库管理员可以跨部门读取，但不会因此让草案或废止制度生效。版本规则使用带时区的查询时间、状态和生效区间选择唯一版本，重叠时返回歧义而不是默认取第一条。

## 验证结果

- 权限与版本专项测试：11 项通过。
- 全部 Python 回归：35 项通过，1 项 pgvector 集成测试因本机未提供 Docker 数据库而明确跳过。
- 权限拒绝文案测试确认不会暴露受限文档标题和 `document_id`。
- 当前版、历史版、未来草案、重叠版本和无时区时间均有独立测试。

## 遇到的问题与取舍

## 我能口述的标准答案

权限过滤必须在召回正文进入模型之前完成，因为 Prompt 只能约束输出，不能撤销已经泄露给模型的输入。版本选择也不是按版本号字符串取最大值，而是结合状态、生效时间、失效时间和用户询问的历史时间；如果两个版本同时符合，就拒绝并要求澄清。

## 面试追问

- 知识库管理员为什么也不能默认看到未来草案的答案？
- 权限拒绝为什么不能返回命中的受限文档标题？
- 为什么重叠生效版本不能直接取版本号最大的？
