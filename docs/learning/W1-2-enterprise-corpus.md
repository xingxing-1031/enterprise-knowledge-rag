# W1-2：版本化企业制度语料

## 本阶段目标

建立能够真实验证版本、生效时间、部门权限、表格和拒答能力的企业制度语料。

## 业务问题

如果知识库只有几篇互不冲突的说明文档，混合检索很容易得到好看的自测结果，但无法验证企业业务中最容易出错的旧版本、权限和相似制度问题。

## 我的实现

构造了人力、财务、采购、信息安全和行政五类制度及流程。语料包含同一制度的旧版、现行版和未来草案，以及部门可见、受限、表格、例外条款和跨章节内容。所有文档都明确标记为项目合成材料。

## 验证结果

- 文档文件：10 份。
- 当前生效版本：7 份。
- 历史失效版本：2 份。
- 未来草案：1 份。
- 部门可见文档：2 份。
- 受限文档：1 份。
- 语料契约测试：6 项通过。

## 遇到的问题与取舍

第一次测试直接使用 `DocumentRecord` 校验 front matter，发现 `content_hash` 和 `indexed_at` 缺失。二者应由索引过程生成，不应要求人工维护，因此测试改为模拟解析器计算哈希并写入固定索引时间。

## 我能口述的标准答案

企业 RAG 的难点不只是找相似文本，还要确认这份制度是否生效、是不是当前版本、用户有没有权限。为了让这些问题可以被测试，我没有只放独立 FAQ，而是主动构造了同一制度的旧版、现行版和未来草案，并加入部门和受限文档。这样后续可以分别评测召回、版本选择和权限泄漏，而不是只看最终回答像不像。

## 面试追问

- 为什么未来草案不能只依赖向量相似度过滤？
- 为什么权限过滤必须发生在片段进入模型之前？
