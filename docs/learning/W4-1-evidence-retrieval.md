# W4-1：Reranker 与最小充分证据

## 本阶段目标

在授权和版本正确的召回结果上完成精排，并构造可供回答模型使用的最小充分证据。

## 业务问题

召回 Top-K 往往包含重复章节、同一制度不同版本和与问题只有弱相关的片段。把这些内容全部交给模型会增加 token、干扰回答，甚至造成版本冲突。Reranker 只能重新排序，不能生成召回层没有的证据。

## 我的实现

Reranker 适配器严格校验输入候选数与返回分数数目，并只对已有 `chunk_id` 重排。检索服务先按用户权限和查询时间选出唯一文档版本，再执行 BM25、向量、RRF 和精排。证据构建器按内容哈希去重、拒绝同一文档的冲突版本，并限制条数和 token 预算。

## 验证结果

- Reranker、检索编排和证据构建专项测试：8 项通过。
- 全部 Python 回归：51 项通过，1 项 pgvector 环境测试明确跳过。
- 测试确认受限文档版本不会传入向量后端，Reranker 不会引入新 `chunk_id`，重复内容和冲突版本不会同时进入证据。

## 遇到的问题与取舍

版本歧义不能因为知识库中存在其他可回答文档就泄露冲突内容。当前服务会排除歧义版本；如果没有剩余可信候选，则返回 `version_ambiguous`，而不是默认选择排序第一的版本。

## 我能口述的标准答案

Reranker 不是召回器，它只能在已经召回的候选中重新判断问题和片段的相关性。如果正确片段根本没有被 BM25 或向量召回，精排再强也没用。因此我分别评测 Recall@K 和精排后的排名，并在生成前再构造最小充分证据，减少重复和冲突内容对模型的干扰。
