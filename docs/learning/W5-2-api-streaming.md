# W5-2：可信会话、FastAPI 与 SSE

## 本阶段目标

通过稳定 API 暴露企业 RAG 工作流，同时保证客户端不能伪装管理员，普通用户看不到内部 Trace 和错误细节。

## 业务问题

如果请求体允许传 `role=admin`，任何访问者都能提权。把完整 Trace 或后端异常直接返回也会暴露受限文档、内部结构和运维信息。用户又需要看到系统是否在处理，因此需要安全的阶段事件。

## 我的实现

身份由服务器会话解析器注入，聊天请求模型禁止额外字段。普通 `/chat` 只返回结果和引用；SSE 只发送中文阶段、状态和最终结果，不包含 Prompt、隐藏思考和原始候选。索引接口只允许知识库管理员访问，并限制请求体大小和 CORS 来源。

## 验证结果

- API 与 SSE 聚焦测试：`7 passed`。
- 全量 Python 回归：`73 passed, 1 skipped`。
- Ruff 规则检查和格式检查：全部通过。
- 跳过项是真实 PostgreSQL/pgvector 往返测试；当前 Codex 终端未发现 Docker，因此不能宣称该项已通过。

## 遇到的问题与取舍

FastAPI 的 `TestClient` 目前会报告 Starlette 关于 `httpx` 的弃用警告。这是依赖兼容提示，不是接口行为失败；本阶段保留警告证据，后续在锁定交付依赖版本时统一处理，避免为了消除提示引入未经验证的依赖替换。

SSE 当前在工作流完成后按 Trace 顺序输出阶段和结果，足以验证公开事件契约，但不等于真正逐节点实时推送。接入具体运行服务时需要把事件生产与工作流执行连接起来，再验证断线、超时和客户端取消。

## 我能口述的标准答案

客户端提交的身份不可信，所以请求体只有问题、会话和查询时间，角色由服务器配置或认证会话提供。SSE 展示的是可观察的工作阶段，不是模型思维链；这样用户能看到进度，但不会暴露 Prompt、敏感正文或内部错误。
