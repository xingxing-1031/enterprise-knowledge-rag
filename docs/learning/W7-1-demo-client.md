# W7-1：企业知识工作台

## 本阶段目标

把真实 API 能力转化为可演示、可核验的中文 Web 工作台，而不是只展示一个输入框和模型文本。

## 业务问题

企业制度问答的重点不仅是“回答了什么”，还要让用户看见当前身份、处理状态、文档版本、章节、原文引用和拒答原因。桌面端需要便于同时核对答案与证据，手机端又不能把双栏强行缩小。

## 我的实现

前端使用 React 18、TypeScript、Vite 和 Lucide。桌面端采用导航、对话和引用台账三段式布局；移动端改为底部导航和证据抽屉。页面包含知识问答、可见知识库和评测概览，覆盖空状态、加载、成功、降级、拒答、失败和部分接口失败。

SSE 客户端解析公开中文阶段与最终结果，不读取内部 Trace。会话、知识库和评测并行请求使用 `Promise.allSettled`，单个接口失败时保留其余可信结果。普通用户看到中文部门和状态，文档 ID、chunk ID、BM25、vector 等审计标识保留英文。

## 验证结果

- 前端组件与 SSE 测试：`3 passed`。
- TypeScript 与 Vite 生产构建：通过。
- 生产包：JavaScript gzip `52.51 kB`，CSS gzip `4.17 kB`。
- `npm audit`：`0 vulnerabilities`。
- 1440 桌面视口：DOM 宽度与视口一致，无页面横向溢出，三栏尺寸稳定。
- 390 移动视口：无横向溢出，底部导航、输入区与证据抽屉位置稳定。
- 360 浏览器截图在本地页面访问策略处被阻止，未绕过限制；已实现 380 与 760 两级 CSS 断点，但仍需在 CI Playwright 中补齐 360 截图证据。

## 遇到的问题与取舍

最初依赖树混用了 Vite 6 与 Vitest 内置的 Vite 5 类型，随后旧版本审计又存在 high/critical 开发工具漏洞。我没有使用 `--force` 掩盖冲突，而是把 Vite、React 插件和 Vitest 统一升级为互相兼容的版本，重新通过构建、测试和零漏洞审计。

页面没有做营销式大屏和装饰卡片，而是直接进入高频查询。视觉记忆点放在右侧“引用台账”的编号证据线，其他区域保持安静，避免视觉效果压过制度核验任务。

## 我能口述的标准答案

前端只展示后端返回的可信结果，不在浏览器执行检索、权限判断或模型调用。桌面端让答案和证据并排核对，移动端把证据变成底部抽屉。SSE 展示的是公开工作阶段，不是思维链。三个元数据接口并行请求，但使用 allSettled 隔离故障，所以知识库暂时失败不会把已经拿到的可信身份一起丢掉。
