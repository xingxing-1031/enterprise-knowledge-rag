# 企析 Agent 通用工具与企业能力增强设计

## 目标

将项目二定位为“企析｜企业专业智能助理”，在保留企业知识库 RAG、经营数据分析和按需多 Agent 协作的基础上，增加可治理的通用 MCP 工具能力。用户可以自然语言请求普通对话、时间、天气、新闻、网页摘要和汇率；企业制度问题继续走知识 Agent，经营指标问题继续走数据 Agent，跨域问题走协作流程。

本轮目标是强化 Agent 应用能力展示，适合实习面试演示；不建设多租户 SaaS、任意数据库接入、账号计费或任意远程 MCP 安装体系。

## 架构

```text
用户请求
  -> Supervisor
     -> General Agent -> Common MCP Server
     -> Knowledge Agent -> 受治理企业 RAG
     -> Data Agent -> 项目一内部 Data API
     -> Collaboration -> Knowledge + Data + Synthesis + Review
```

项目二新增通用工具调用循环。General Agent 只接收经白名单发现的工具 Schema，根据模型结构化决策调用工具，把结构化结果追加到上下文后继续生成回答。项目一原有报告导出 MCP 保持独立，不改变核心 SQL/RAG 安全链路。

## 通用 MCP 工具

新增独立 Common MCP Server，使用 Python MCP SDK 的 FastMCP 和 stdio 传输：

- `time.now`：输入 IANA 时区，默认 `Asia/Shanghai`，本地计算当前时间。
- `weather.current`：输入城市，使用 Open-Meteo 地理编码和天气接口；只返回当前天气与来源时间。
- `web.search`：通过配置的搜索服务查询公开网页；未配置 API Key 时返回明确降级信息。
- `web.fetch_summary`：抓取用户指定的公开网页，限制协议、响应大小和超时时间，提取正文后交给模型摘要。
- `exchange.rate`：查询公开汇率服务；记录基准币种、目标币种和报价时间。

工具输入输出使用 Pydantic Schema。工具调用不允许写入本地数据库、访问内部服务或执行系统命令。

## 安全与可靠性

- 工具名称、输入字段和网络目标使用白名单。
- 每次调用设置总超时、有限重试和最大响应大小。
- 外部工具失败时，General Agent 返回可解释的降级回答，不编造实时数据。
- 工具调用记录工具名、规范化参数哈希、耗时、状态和错误类型；不记录 API Key 和完整敏感响应。
- 网页抓取仅允许 `http/https`，阻止内网地址、文件协议和重定向到私网。
- General Agent 最多执行有限步数，防止模型循环调用工具。
- 企业 RAG 和 Data Agent 不允许被通用外部 MCP 绕过；内部数据仍走既有权限、引用、SQL AST 和业务一致性校验。

## 上下文与交互

工具结果采用结构化消息进入当前会话上下文，并保留工具来源和时间戳。上下文超出预算时优先压缩旧对话，保留用户当前问题、工具结果摘要和企业证据 ID。SSE 新增工具发现、工具调用中、工具完成和工具降级事件，前端展示当前阶段与来源。

## 测试与评测

- MCP Server：工具发现、Schema 校验、正常结果、超时、外部服务错误和恶意 URL 测试。
- General Agent：能识别需要工具的请求、选择正确工具、将结果用于后续回答，并在工具不可用时降级。
- Supervisor：时间/天气/公开信息仍路由到 General；企业制度、经营数据和跨域问题保持原路由。
- 回归测试：知识 Agent、Data Agent、协作审核和原有报告导出不受影响。
- 评测报告记录路由准确率、工具选择准确率、工具调用成功率、引用完整性和降级率。

## 验收标准

1. 可以通过自然语言查询北京时间、城市天气、公开新闻、网页摘要和汇率。
2. 工具调用结果在回答中可追溯，工具故障不会导致编造实时信息。
3. 企业制度和经营分析仍使用原有受治理链路。
4. 所有新增能力有自动化测试，前端和 SSE 展示不破坏现有功能。
5. 文档能够清楚解释 MCP、工具调用循环、上下文管理、安全边界和评测方法。
