# 企业知识库管理员控制台设计

## 目标

将项目二从同时提供员工问答和知识库管理的 RAG 工作台，收口为仅供知识库管理员使用的 RAG 管理控制面。普通用户不再直接登录、查看文档元数据、调用公开问答接口或访问评测数据；项目一“企析”通过内部服务令牌调用证据接口，成为员工使用企业知识的唯一产品入口。

本次改造保留现有文档解析、清洗、切分、权限过滤、版本治理、混合检索、RRF、Reranker、证据构建、引用校验、拒答和评测能力，不重写 RAG 核心。

## 产品边界

### 项目一负责

- 面向员工和管理者的对话体验。
- 用户身份、上下文管理、Agent 路由和跨 Agent 协作。
- 通过 `X-Internal-Token` 调用项目二的 `/internal/evidence`。
- 根据调用者身份向项目二传递受限的角色和部门上下文。

### 项目二负责

- 管理员登录和知识库管理。
- 文档上传、解析、清洗预览、审核和建立索引。
- 文档版本、可见范围、停用、恢复、重新索引和永久删除。
- 管理员专用检索实验室。
- RAG 评测、运行状态和管理操作审计。
- 为项目一提供受内部令牌保护的证据接口。

### 不在范围内

- 普通员工登录项目二。
- 项目二提供面向员工的聊天产品。
- 注册、找回密码、组织成员管理或多租户管理。
- 可视化搭建任意 RAG 流程或动态注册数据源。
- 将项目二扩展为通用低代码 Agent 平台。

## 身份与访问控制

项目二的网页登录只保留一个固定演示身份：`knowledge-admin-demo`。服务端只接受该账号登录，并在签名 HttpOnly Cookie 中保存 `knowledge_admin` 身份。原有员工和部门管理员演示账号从登录配置、登录页和测试契约中移除。

接口分为三类：

1. 公开存活接口：`GET /health`、`GET /ready`，只返回服务状态，不暴露文档、索引或评测信息。
2. 管理接口：会话、文档、导入、索引、检索实验室、评测和审计接口，全部要求 `knowledge_admin` 会话。
3. 内部证据接口：`POST /internal/evidence`，不使用浏览器会话，只接受正确的 `X-Internal-Token`。它继续根据项目一传入的角色与部门构造受限检索上下文。

原有 `/chat`、`/chat/stream` 和 `/chat/clear` 不再作为普通用户能力。管理员的检索调试使用独立的管理接口，避免把调试行为和员工问答混为一谈。

服务端不能因为前端隐藏菜单就默认安全。所有管理接口必须在依赖层验证管理员身份；未登录返回 `401`，非管理员返回不泄露资源信息的 `403`。

## 信息架构

管理控制台采用五个一级页面：

### 总览

- 服务健康状态和索引就绪状态。
- 文档总数、有效版本数、已停用版本数、切片数和向量数。
- 待审核、处理失败和需要重新索引的导入任务。
- 最近一次评测的核心指标与运行时间。
- 最近管理操作，包括导入、批准、停用、恢复、重新索引和删除。

总览是运行状态入口，不复制文档表格或完整评测报告。

### 文档库

- 按标题或文档编号搜索。
- 按部门、文档类型、可见范围和生命周期状态筛选。
- 表格展示标题、当前版本、部门、可见范围、状态、切片数量和更新时间。
- 选择文档后在详情面板查看元数据、版本关系、索引信息和允许角色。
- 支持重新索引、停用、恢复和永久删除。
- 危险操作不放在列表主操作位，统一进入详情面板的危险操作区。

### 导入审核

- 上传 PDF、DOCX、Markdown 或 TXT。
- 填写文档编号、标题、类型、部门、可见范围、允许角色、版本、生效区间、替代版本和主题标签。
- 上传后只生成解析与清洗预览，不直接进入可检索索引。
- 审核页展示字符、段落、表格、页数、清洗问题和标准化正文预览。
- 管理员确认后建立切片与向量索引。

### 检索实验室

检索实验室是管理员调试工具，不是聊天界面。

- 输入测试问题、时间点、Top-K 和模拟访问上下文。
- 模拟身份只影响本次受限检索，不创建新的登录身份。
- 展示文档路由、BM25、向量召回、RRF、Rerank、权限过滤和证据构建阶段。
- 每一阶段显示候选数、保留或淘汰原因、分数和耗时。
- 结果区展示最终证据片段、引用信息、版本、生效日期和拒答或降级原因。
- 不允许直接读取未授权候选的正文；权限过滤结果只显示安全的统计与原因代码。

### 评测中心

- 展示数据集、代码或配置快照、运行状态和完成时间。
- 展示 Recall@K、MRR、引用正确率、证据覆盖率、拒答准确率和延迟。
- 比较向量基线、混合检索和启用 Reranker 的已有评测结果。
- 展示失败用例及其安全查询、期望行为和失败阶段。
- 不在浏览器中直接修改 frozen holdout 数据。

## 文档生命周期

文档状态流转为：

```text
uploaded -> parsed -> needs_review -> indexed -> inactive
                                  \-> quarantined / failed
inactive -> indexed
indexed / inactive -> deleted
```

`inactive` 表示文档立即退出父文档路由、BM25、向量召回、RRF 和 Rerank，但保留源文件、版本、切片、向量和历史审计，可以恢复。

永久删除执行以下动作：

- 删除源文件或受管上传文件。
- 删除该文档版本的文档记录。
- 级联删除切片、向量和相关索引记录。
- 清除不能再使用的导入任务正文与预览。
- 保留不含正文、切片或敏感标题内容的删除审计墓碑。

永久删除必须在详情面板输入当前显示的文档标题完成确认。服务端校验文档状态、确认文本和目标版本；前端确认不能替代服务端验证。删除成功后立即从管理列表和检索语料中消失，不支持恢复。

## 后端接口

现有接口按以下原则调整：

- `POST /auth/login`：只匹配知识库管理员账号。
- `GET /session`、`POST /auth/logout`：保留。
- `GET /documents`：改为管理员接口并返回管理所需的生命周期和索引摘要。
- `POST /documents/index`：保留管理员权限。
- `POST /documents/{document_id}/versions/{version}/deactivate`：停用指定版本。
- `POST /documents/{document_id}/versions/{version}/restore`：恢复指定版本并重新纳入检索。
- `POST /documents/{document_id}/versions/{version}/reindex`：重建该版本切片和向量。
- `DELETE /documents/{document_id}/versions/{version}`：执行带确认文本的永久删除。
- `/knowledge/imports` 系列：继续要求管理员权限。
- `POST /admin/retrieval/debug`：返回安全的分阶段检索调试结果。
- `GET /evaluations/latest` 和评测列表或详情接口：全部要求管理员权限。
- `GET /admin/audit`：返回管理操作审计摘要。
- `POST /internal/evidence`：保持内部令牌认证与现有返回契约兼容。
- `/chat`、`/chat/stream`、`/chat/clear`：从公开产品契约移除。

接口错误采用稳定中文消息。数据库异常、模型异常和文件路径不会直接返回浏览器。

## 数据与审计

数据库需要记录文档生命周期状态和管理操作审计。审计至少包含：事件编号、操作类型、管理员标识、文档编号的不可逆摘要、版本、结果、原因代码和时间。永久删除后审计记录不得保留正文、切片、向量、原始文件路径或可恢复的敏感元数据。

索引与文档状态必须一致：只有当前可用且处于 `indexed` 状态的版本进入检索。停用和永久删除完成后，新的检索请求不能再命中目标版本。

## 界面与视觉系统

界面采用真实企业内部运维控制台风格，强调扫描效率和可重复操作：

- 深石墨色导航、冷白工作区、蓝色主操作。
- 绿色表示健康或完成，琥珀色表示待审核或降级，红色只用于失败和危险操作。
- 使用全宽工作区、数据表格、筛选栏、分栏检查器和状态时间线。
- 卡片只用于独立指标或重复评测结果，不将完整页面区块包装成悬浮卡片。
- 圆角不超过 8px，图标使用现有 Lucide 图标库。
- 数据编号、分数和耗时使用等宽字体；正文使用清晰的中文无衬线字体栈。
- 不使用营销 Hero、装饰性渐变、发光球体或大面积单色主题。

产品的识别性元素是“检索流水线”：候选文档沿阶段轨道展示数量、排序和淘汰原因，让管理员一眼看清一条查询如何从召回进入融合、重排和证据构建。

桌面端优先支持高密度管理。手机端使用底部导航或紧凑菜单，表格切换为摘要列表与详情抽屉；上传、审核、停用和删除按钮保持至少 44px 触控尺寸，不产生页面级横向滚动。

## 状态与错误处理

- 未登录：进入单管理员登录页。
- 会话过期：清空前端管理数据并返回登录页。
- 部分统计失败：保留其他可用数据并标注具体模块不可用。
- 上传失败：保留已填写元数据，显示格式或大小原因。
- 解析或清洗失败：任务进入失败或隔离状态，不允许批准。
- 停用、恢复、重建索引和删除：显示进行中状态，防止重复提交。
- 永久删除失败：保持详情面板，说明文档仍然存在，不进行乐观删除。
- 检索实验失败：展示失败阶段和安全错误类型，不暴露调用栈。
- 评测文件不存在：显示尚未运行及可执行的运维命令说明，不伪造零分指标。

## 测试与验收

### 权限验收

- 员工和部门管理员演示账号不能登录。
- 未登录请求所有管理接口均返回 `401`。
- 非管理员测试身份请求管理接口返回 `403`。
- 正确内部令牌仍可调用 `/internal/evidence`。
- 无效内部令牌不能读取证据、文档元数据或评测结果。

### 生命周期验收

- 已入库文档能够被受权 Agent 检索。
- 停用后立即不再进入检索，恢复后重新可检索。
- 永久删除同时移除源文件、文档记录、切片和向量。
- 删除后同一版本不再出现在列表或检索结果中。
- 删除审计记录不包含正文和可恢复敏感信息。

### 界面验收

- 登录页只展示管理员身份。
- 导航不再出现智能助手页面。
- 五个管理页面均具有加载、空、失败和完成状态。
- 检索流水线能展示各阶段候选变化与耗时。
- 桌面 1280x720 和手机 390x844 无页面级横向滚动或控件重叠。
- 键盘可以完成导航、筛选、上传、审核和删除确认。
- 所有图标按钮具有可访问名称，焦点状态可见。

### 回归验收

- 后端 Pytest、Ruff 全部通过。
- 前端 Vitest、TypeScript 构建和 Playwright 响应式检查通过。
- 项目一调用项目二内部证据接口的契约测试通过。
- 部署后的 `/health` 与 `/ready` 正常，管理员登录和内部证据调用分别完成线上冒烟测试。

## 交付边界

该控制台是单管理员演示系统，使用合成企业制度语料。它证明 RAG 服务治理、权限隔离、文档生命周期、检索可解释性和评测闭环，不宣称具备正式企业 SSO、多租户、密钥轮换、分布式任务队列、对象存储容灾或生产 SLA。
