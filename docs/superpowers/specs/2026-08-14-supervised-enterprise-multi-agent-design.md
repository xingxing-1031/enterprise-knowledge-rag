# 企业运营多 Agent 升级设计

## 目标

将 `8010` 的企业知识库助手升级为面向企业运营的按需多 Agent 助手。系统既能处理普通聊天，也能对企业制度、经营数据和跨域复盘任务选择正确的执行路径，并保留权限、版本、引用、SQL 安全、审批与审计边界。

## 核心原则

- 简单问题不启动多 Agent：普通聊天走通用对话，单一制度问题走知识 Agent，单一经营问题走数据 Agent。
- 只有同时需要企业知识、经营数据或报告交付的复杂任务才由 Supervisor 拆解并协作执行。
- 企业事实必须来自授权知识证据；经营数字必须来自受治理 SQL 结果；通用模型不得补写这两类事实。
- 项目一继续拥有 SQL、业务 Skill、审批、MCP 导出实现，项目二通过内部 HTTP 契约调用，不复制代码。
- 所有公开进度只展示角色、任务、工具与状态，不展示隐藏思维链。

## 路由与角色

Supervisor 输出结构化 `AgentPlan`，模式为 `general`、`knowledge`、`data` 或 `collaboration`。

- 通用对话 Agent：回答闲聊、概念解释、写作与学习类问题；明确不拥有企业事实权限。
- 知识 Agent：复用现有层级 RAG、混合检索、Reranker、权限、版本、证据覆盖、引用校验与拒答。
- 数据 Agent：通过项目一内部接口调用经营 Skill、Text-to-SQL、SQLGlot AST、业务一致性校验、审批与图表能力。
- 综合 Agent：仅根据子 Agent 的结构化结果生成答案或报告，不自行新增企业事实和数字。
- 审核 Agent：确定性检查任务完成度、引用、数据证据、权限与失败状态；必要证据缺失则可信降级或拒答。

## 执行流程

```text
用户问题
  -> Supervisor（路由、子任务、完成条件）
  -> general：通用对话 Agent -> 审核
  -> knowledge：知识 Agent -> 审核
  -> data：数据 Agent -> 审核
  -> collaboration：知识 Agent + 数据 Agent -> 综合 Agent -> 审核
  -> 答案、引用、图表/报告、公开执行轨迹
```

Supervisor 使用结构化模型输出，模型不可用时由保守规则回退。协作任务可以并行执行知识和数据子任务；任何一个核心子任务失败时不伪装为完整成功。

## 接口与状态

`ChatResult` 增加可选的 `agent_mode`、`agents`、`task_plan`、`tool_calls`、`data_result` 与 `review` 字段，保持原有客户端兼容。SSE 增加 `supervisor`、`knowledge_agent`、`data_agent`、`synthesis_agent`、`review_agent` 阶段。

项目一新增受 `X-Internal-Token` 保护的 `/internal/agent` 接口，接收用户、角色、部门、问题、会话与请求 ID，返回 Skill、数据结论、查询证据、图表、报告和工具轨迹。项目二不接触项目一数据库凭据。

## 上下文策略

会话按用户与 session 隔离。Supervisor 只接收当前问题、有限历史和结构化摘要。子 Agent 只获得完成自身任务所需上下文；知识证据、数据证据和通用对话内容分区保存，防止普通聊天污染企业证据。

## 安全与失败处理

- 企业问题不能在 RAG 证据不足后降级为通用常识回答。
- 数据 Agent 超时或不可用时返回明确降级原因，知识结论仍可单独呈现。
- 项目一内部接口必须验证共享令牌，并继承原有角色、限流、审批与只读 SQL 规则。
- 综合 Agent 输出后执行确定性证据审核；引用缺失、工具失败、任务未完成均进入降级或拒答。
- 通用对话限制输出长度、模型超时与历史预算，不允许工具调用和企业事实声明。

## 前端

聊天页改为“企业运营智能助手”，保留知识库与评测管理页。结果区展示当前模式、参与 Agent、任务步骤、工具状态、知识引用、数据结果与审核状态；普通聊天保持简洁，不展示空的企业面板。

## 评测

新增独立 development 集，覆盖通用、知识、数据、协作、权限和故障六类任务。至少统计：Supervisor 路由准确率、Agent 选择准确率、复杂任务完成率、企业证据完整率、拒答准确率、工具成功率、P50/P95 延迟。所有简历数字必须引用保存的样本级报告，不称为通用准确率。

## 验收标准

1. 普通聊天能够正常回答，且不会伪造企业引用。
2. 单一知识与单一数据问题分别只调用必要 Agent。
3. 跨知识与数据的复杂问题自动拆解、协作、综合并审核。
4. `8010` 前端能展示模式、Agent、任务和证据，原有知识库功能不回退。
5. 项目一内部接口通过令牌保护，两个项目的完整测试、静态检查和前端构建通过。
6. 公网部署健康，保存可复现的多 Agent development 评测报告与简历/面试材料。
